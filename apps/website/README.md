# Website — TanStack Start foundation

Minimal TanStack Start application. All content is typed mock data: no database, authentication, GSI connection, persistence, or external data services. The ReUI preset is configured and the static shadcn `sidebar-09` example is available at `/sidebar`.

## Commands

From the repository root:

- `pnpm dev` — development on port 5173.
- `pnpm --filter website build` — generate the file-based route tree, build client/server, and typecheck.
- `pnpm --filter website start` — serve the production Node build (default port 3000; set `PORT` to override).
- `pnpm ready` — repository formatting, lint, tests, and builds.

Deploy the complete `apps/website/.output` directory and run `node .output/server/index.mjs` from the application directory. The deployment adapter is Nitro’s explicit `node-server` preset in `vite.config.ts`; changing that adapter does not require changing routes or server functions. Node is provisional because the requested runtime was a placeholder. Nitro 3 is currently an RC, pinned by the workspace catalog/lockfile.

## Routes and SSR decisions

- `__root`: default/full SSR (`ssr: true`) because the HTML document shell must be available before hydration; also wraps error and not-found responses.
- `/`: default/full SSR (`ssr: true`) because the static placeholder has no browser-only dependencies; the unawaited mock loader promise streams through Suspense/Await.

No data-only or SPA route is needed yet. Choose `ssr: 'data-only'` or `ssr: false` on a future route only when its requirements justify it. Start’s built-in server entry uses `createStartHandler(defaultStreamHandler)`; this app retains that full-document streaming pipeline.

## Boundaries and validation

`routes/index.tsx` imports only the client-safe `createServerFn` wrapper. Its handler dynamically imports `server/workspace.server.ts`, which is guarded by `@tanstack/react-start/server-only`. Import protection fails both dev and production builds if server-only code reaches the client graph. Shared types and validators contain no server dependencies.

The search parameter `view` accepts `canvas` or `outline`; missing/invalid values default to `canvas`. Loader dependencies use the validated value. The GET server function independently validates its input and returns `Promise<MockWorkspace>`. A 30ms mock delay makes streaming visible; it performs no I/O. The two plain links exercise client-side routing and the RPC boundary, not an editor implementation.

`src/routeTree.gen.ts` is generated by the Start plugin and checked in; do not edit it manually. `verbatimModuleSyntax` is disabled following Start’s bundling guidance. `skipLibCheck` is enabled only for this app to avoid checking dependency declarations; application code stays strict.

## ReUI setup status

Initialized with `shadcn init --preset bJMSkwJm`: Base Nova, Stone, Inter, and Hugeicons. Tailwind v4 is configured through its Vite plugin, with global CSS linked from the root document. `components.json` registers `@reui` and the `@/*` source alias.

Installed `@reui/c-sidebar-2` through the registry CLI using the exact item supplied by the user. The MCP still requires authentication, so the skill’s documented CLI fallback was used. That component remains available in `src/components/examples/c-sidebar-2.tsx`.

`/sidebar` now renders shadcn `sidebar-09`, installed with `pnpm dlx shadcn@latest add sidebar-09`, retaining the existing Base Nova primitives and theme. It uses the registry’s two-column mail sidebar and placeholder content inside TooltipProvider. Full SSR renders the static initial markup; interactive controls hydrate on the client. The navigation uses the stashed HUD Studio destinations: `/huds`, `/editor`, `/templates`, `/assets`, and `/settings`, grouped under Workspace, Library, and Preferences. These full-SSR routes share the existing sidebar layout and static placeholder content; no editor, persistence, backend, or authentication is restored. Only `/editor` displays the secondary sidebar; other routes use the main icon rail and give the remaining width to their content. `/sidebar` remains a preview of the main navigation. Collapse resets on reload; no server-side cookie restoration is added.
